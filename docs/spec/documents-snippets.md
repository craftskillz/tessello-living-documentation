# Documents: snippets

Atlas page: `features/documents/snippets.md` (business rules R1–R12). Atlas answers: Q-029 to Q-034. Rules of the original not changed here are kept. Directive syntax: ADR 0005.

## Catalog

1. **25 kinds**: the original's 27 minus **Local search** (browser find instead) and **Diagram** (Diagrams is a separate Tessello module; existing diagram links render as plain images that enlarge on click). The **Kanban board** snippet stays; its behavior: Kanban round.
2. Picker, search, forms, the table grid editor and the save rules (R1–R3, R5–R11) are kept. Every default text and tooltip is translated (cross-cutting language rule).

## Changed from the original

3. **Source positions**: every rendered block carries its source line range. Edit, Delete and Insert-after use it, and check before writing that the source there is still what was rendered. No matching by order among blocks of the same shape.
4. **Failures** keep the dialog open with its content and show the error inside it with **Retry**. On a conflict the Document is re-read and the block located again by its content: found → Retry applies there; not found → "This block changed on disk" with **Copy Markdown**.
5. **Reopen in their form**: the original's 21 kinds; Mermaid Builder charts (pie, timeline, tree view, sequence) parsed back into builder rows, else a plain code block; layout columns (options editable, column content untouched); attachment links as links (text and target). Emojis stay plain text.
6. **File attachment** from the right-click insert opens the file chooser, as from the editor. Escape closes the dialog everywhere. The unused "detected type" messages are removed.
7. **Layout** form: 2–4 columns; documents with up to 6 render.
8. **Content rules**: `|` in a table cell is escaped as `\|`; Shift+Enter in a cell of the table grid writes `<br>` at the caret (a line break in the cell, the row staying on one line); tree names are drawn as typed (no "/ makes folders" hint); pie weights are numbers ≥ 0 with no total cap.
9. **Table options** (decided with the User, 2026-11-26): the Table form offers a density (**Default**, **Intermediate**, **Compact**) and check boxes: **Borders**, **Softened borders**, **Rounded**, **Striped** and **Full** (Borders and Softened borders exclusive, Striped and Full exclusive). Softened borders draw the same lines as Borders in the soft tone (the colour's light shade, or the rows' separator without colour). Rounded draws a rounded outer frame on any table, with or without Borders (without them: no vertical lines inside). Written as `<!-- table-style: compact|intermediate -->`, `<!-- table-fill: striped|full -->`, `<!-- table-border: bordered|soft-bordered -->`, `<!-- table-rounded -->`, `<!-- table-color: … -->`, in that order, each only when set. The original's `table-style: striped|full` still read (its Full as Full + Rounded, its old look); the original ignores the new lines. The form's grid shows the table exactly as the Document renders it.
10. **Card block** (ticket 40, decided with the User, 2026-11-27): a Structure snippet labelled **Card**, written `<!-- card: Title | style: bristol | color: sky | width: 1/2 | align: right -->` … `<!-- /card -->` around free Markdown (only the options that differ from plain, full width, left; no title gives `<!-- card -->` or `<!-- card | style: … -->`). The title stays in the comment: out of the table of contents and the sections; `|` becomes `/` and `--` an em dash in it. Styles: **Plain** (a frame with a title bar, following the theme), **Bristol card** (cream paper with light squares, punched holes across the top, one in every three places: ● · · ● · · ●, a red title over a red rule from edge to edge) and **Playing card** (white face, rounded corners, a shadow, a double lozenge ◈ in both top corners, a centred serif title); the paper ones stay light in a dark Document. **Background** (`color:`, written after `style`): the style's own by default, or one of twelve: White, Cream, Lemon, Peach, Rose, Lavender, Sky, Mint, Sage, Slate, Navy, Forest; the ink of the text, of the title and the plain frame are chosen with it, and a coloured card keeps its colours in a dark Document. Widths are the images' presets; a narrower card stays alone on its line (two side by side go in a Layout); full width under 640 px. Cards nest and go inside and around Layouts. Reopened from the reading view (Edit card, Delete card), its content kept byte for byte. The HTML view, its templates and Download HTML render it.
11. **Table check boxes** (decided with the User, 2026-11-28; no ticket): the Table form's **Check boxes** option writes `<!-- table-checkboxes -->` (after the other table directives) and puts a first column of boxes before the others: blank header, each body row `[ ]` or `[x]` in the Markdown, an empty box written `[ ]`. In the form the column shows as boxes, cannot be deleted, and unticking the option removes it. In the reading a first cell holding `[ ]`, `[x]` (`[X]`) or nothing is a box; any other first cell shows as written. A click ticks or unticks the box at once and writes that cell to the Document, with the version check of the Tag marker writes (a change of the cell on disk refuses, the box comes back); while one tick is being written the others wait; not while the Document is being edited or is read-only. A checked row's other cells are hatched and shown at 55 % opacity. The HTML view and the downloaded HTML show the boxes the same way, not clickable.
12. **Table colour palette** (ticket 33, decided with the User, 2026-11-28): the five table colours (**Info**, **Success**, **Warning**, **Danger**, **Note**) can be recoloured per Project in Project settings › shared settings › **Table colours**: one colour picker per name, committed when the picker closes (not while it is dragged), and a **Restore defaults** button. The User picks one accent per colour; the soft, stripe and text shades, and the dark theme's, are derived from it (soft = 20% accent over white, stripe = 8%, text = accent 45% over black; dark: accent 70% over white and the others from the accent darkened by half). Only the five names, which are fixed, are recoloured; callouts, coloured text and sections and Kanban columns are not. Kept in `.living-doc.json` as `"colorPalette": { "info": "#rrggbb", … }`, only the colours that differ from the defaults (a colour picked back to its default is dropped), `#rrggbb` lower case, in colour order (a `#rgb`, upper case or spaced value written by hand is read as its `#rrggbb`); no colour changed removes the key (Restore defaults too), and no file is created for it. A missing key, a malformed file, an unknown name or an invalid colour gives today's colour for it; the original ignores the key. Because tables are written by name, every Document, old or new, follows the palette: the reading view, the Table form's grid (both under `.document`, light and dark) and the HTML view and Download HTML (light only). A change made on disk by an agent or a teammate is picked up like the other settings; a failed write shows the usual message and the picker shows the previous colour again.
